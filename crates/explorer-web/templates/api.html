JSON API

Every endpoint below is a GET. None of them needs a key, a header or a session. The keys for FCMP++ and Carrot are listed under the block and transaction shapes.

The example responses on this page were recorded from a regtest chain run by monerod's FCMP++ branch, so their heights are small and their transactions spend with FCMP++. Every hash and amount in them is one that chain holds.

The envelope

Every answer takes one of three shapes. 

{"data": { … }, "status": "success"}
{"data": {"title": "Cant find tx: …"}, "status": "fail"}
{"data": null, "message": "…", "status": "error"}

fail means the caller asked for something this explorer will not answer, such as an argument that does not parse or a height past the tip. error means this explorer or its daemon could not answer.

Three answers are not enveloped, because the layers above this API produce them. A request that outlives its deadline gets a bare 504. A request body over the limit gets a 413. A panic caught in a handler gets a 500.

Status codes

The HTTP status says the same thing as the envelope.

CodeMeaning
200The answer is in data.
400The argument is not one this explorer reads, or a limit is over its cap.
404The argument was well formed and the chain does not hold it.
500A bug here.
502The daemon could not be reached, or answered with something unusable.
503This deployment cannot serve the endpoint, because its daemon lacks the call.

GET/api/version

The API revision and the version string of the daemon. api is (major << 16) | minor, which reads 65539 for these shapes. The three git_* fields are always empty, because oxblocks embeds no build metadata. The keys stay because clients index them. oxblocks_version is an extra key, so a client can tell which explorer answered.

A daemon started with --restricted-rpc reports an empty version string. An empty monero_version_full therefore means either a restricted daemon or one that reported nothing, and this response cannot tell you which. oxblocks expects an unrestricted daemon.

GET/api/networkinfo

Twenty-six fields of chain and node state. Four of them are easy to misread.

difficulty and cumulative_difficulty are JSON strings. A parser that holds numbers as doubles loses integers above 253, and cumulative difficulty passed that point long ago.

status is a boolean field of data. It is not the envelope's "status": "success".

tx_pool_size_kbytes holds bytes. The name is wrong and stays wrong, because a correction here would break every client that reads it.

hash_rate is a JSON number. It stops at u64::MAX instead of wrapping. A client backed by doubles should read it as a string out of the raw body when the exact value matters.

GET/api/transaction/<hash>

One transaction, with every ring resolved. Each input lists its ring members with the height, one time key and source transaction of each. This is the only endpoint that resolves rings, because it costs one daemon call for each input. An FCMP++ transaction has no rings to resolve; it costs one call for its tree size instead.

Returns a transaction detail object, and is one of two endpoints that fill its anonymity_set, with /api/search on a transaction hash, which answers through this one. It also serves a transaction in the pool, which reports block_height 0, confirmations 0, and the time it arrived in place of a block timestamp. 

curl -s "$OXBLOCKS/api/transaction/<hash>"

GET/api/transaction/<hash>/paths?block=&from=&output=

The paths through the FCMP++ curve tree of a mined transaction's outputs, as of block, or the tip when it is left out: 50 outputs at most, starting at output from, counted from 0, or output output alone, counted from 1 as the transaction page lists them. Each parameter is a plain number, and an empty one counts as left out. The explorer recomputes each path's hashes from its leaves up and compares the result with the root in block block − 8. root_check is matches when the path of every output in the tree so far holds and reaches that root, fails when one does not or the daemon sends none for an output its lock puts in the tree, and unchecked when no output is in the tree yet or no block carries the root. The paths, the transaction and the root all come from this explorer's daemon, so a match shows they agree with each other, not that the daemon is honest.

Each output carries its unified_id and its last_locked_block. The tree holds the output from that block on. An output in the tree also carries its leaf_idx, its check (holds, broken, unreadable, misshapen or not_the_output, for a path whose leaf is not the output's key and commitment as its transaction records them), and its groups, from the leaves to the root. Each group gives its layer, curve, layer_size, its first member's place in the layer as start, and the ancestor's place in the group as offset. The leaves' group lists its leaves, each with its unified id, kind, output key and commitment. Every other group lists its members as compressed points.

A transaction in the pool is a 404: its outputs have no place in the tree until it is mined and they unlock. So is a block past the tip, and a window that starts past the transaction's last output. 

curl -s "$OXBLOCKS/api/transaction/<hash>/paths"

GET/api/transaction/private/<postfix>

Every transaction whose hash ends with the hex postfix you give. The caller picks the one it wants on its own machine, so the explorer never learns which one that was. Returns txs and missed_txs.

Rings stay unresolved here. Each input carries its amount and key image, and mixins is null, except on an FCMP++ input, which has no ring and reads []. Resolving every ring in the set would cost thousands of calls for a caller that wants one transaction. Ask for that one through /api/transaction.

A postfix is {{ min_postfix_len }} to {{ max_postfix_len }} hex characters. It must also name a set that is large enough to hide in and small enough to serve, which is {{ min_anonymity_set }} to {{ max_private_tx_matches }} expected matches. Those two bounds count transactions rather than characters, so the lengths that qualify move with the size of the chain. On this chain that is {% if postfix_lengths.is_empty() %}no length at all{% else %}{{ postfix_lengths }}{% endif %}.

GET/api/search/<height|hash>

Reads the shape of the argument. A short number is a height. 64 hex characters are tried as a block hash and then as a transaction hash. The object that matches comes back with a title field naming what it is, either "block" or "tx", so a client does not have to inspect the fields to find out.

Addresses are not searchable. Monero has no address index. Building one needs a secret view key, which this explorer never asks for.

GET/health

Liveness and cache occupancy. It sits outside /api and is not enveloped. It answers a plain object. rpc_calls counts calls to the daemon since start, which is not the same as cache misses. One batched fetch of forty hashes is forty misses and one call.

The answer says nothing about the daemon. A health check that fails when the daemon is slow turns one slow dependency into an outage.

Shared shapes

Three objects appear inside more than one response. They are described here once rather than under each endpoint.

Block object

block_height, current_height, hash, size, timestamp, timestamp_utc, and txs, an array of transaction summaries with the coinbase first. current_height is the height of the chain. /api/block reads it from the daemon's chain info, which the explorer holds for a few seconds, and /api/blocks works it out from the depth each header in the range carries.

tree_root is the root of the curve tree the block commits to, in hex, and n_tree_layers is the tree's layer count. Both are null when no tree is reported: below the FCMP++ fork, whose block format has no tree, when the daemon's block does not carry a well-formed tree, and in /api/blocks for a post-fork block whose body the daemon did not return. A tree with no outputs yet has n_tree_layers 0 and a root of zeros. Both fields are in the block's body, after its transaction list, and no header call returns them, so from the fork on /api/blocks fetches every block's body. The root runs eight blocks ahead of the block: block H carries the tree as it stands at height H + 8. A proof whose reference_block is R was therefore checked against the tree_root of block R − 8, not of block R. For a reference block less than eight past the fork, block R − 8 is from before it and no block carries that root.

Transaction summary

coinbase, extra, mixin, payment_id, payment_id8, rct_type, tx_fee, tx_hash, tx_size, tx_version, unlock_time, xmr_inputs, xmr_outputs, reference_block, n_tree_layers and fcmp_pp_proof_size.

reference_block is the height the curve tree was taken at when an FCMP++ transaction's inputs were proven: the tree of every output spendable with that block as the tip. Its root is in the body of block reference_block − 8; see the block object. And n_tree_layers is how many layers that tree had. Both are null for a ring spend and a coinbase. Both sit in the prunable half of the transaction, so they are also null for an FCMP++ transaction that a pruned node no longer holds in full. Its rct_type still reads 7. fcmp_pp_proof_size is the FCMP++ proof's length in bytes, which the input count and the layer count fix, and it is null in the same cases.

mixin is the ring size, not the ring size minus one, and it is 0 for a coinbase. It is also 0 for an FCMP++ transaction, rct_type 7, whose inputs prove membership in the curve tree and so have no ring. Read rct_type before reading a 0 here as no anonymity set.

xmr_inputs and xmr_outputs are 0 wherever the protocol hides the amount. They carry real values in two cases: a pre-RingCT transaction, where the chain itself is in the clear, and every coinbase, because a block reward is public. A version 2 coinbase is still in the clear, so the version number alone does not tell you whether an amount is visible. Read rct_type and coinbase together.

Transaction detail

Everything in the summary, plus block_height, confirmations, current_height, timestamp, timestamp_utc, inputs, outputs and anonymity_set.

anonymity_set is how many outputs the curve tree held as of reference_block, which is how many outputs each FCMP++ input could be spending. It is null for a ring spend, for a transaction still in the pool, wherever reference_block is null, on every endpoint but /api/transaction and a transaction found through /api/search, and when the daemon cannot answer, as one from before FCMP++ cannot.

inputs is null for a coinbase transaction, which spends nothing. It is not []. Each input carries amount, key_image and mixins. mixins is itself null when the ring was not resolved, either because the endpoint does not resolve rings or because the daemon refused the lookup. An empty array would say the input has no ring members, which is a different statement, and it is exactly the statement an FCMP++ input makes: its mixins is [] on every endpoint, because there is no ring to withhold.

Each output carries amount, public_key, view_tag, encrypted_janus_anchor and unified_id. unified_id is the output's index among every output on the chain, of every amount, which a wallet uses to ask for the output's path through the curve tree. It is null for a transaction still in the pool and on a daemon from before FCMP++, which does not report it. public_key is the one-time address, Carrot's included. view_tag is two hex characters for an output from before Carrot and six for a Carrot output, and null for an output from before view tags. encrypted_janus_anchor is 32 hex characters on a Carrot output and null on every other.

Limits

Each request costs the operator's daemon network calls. These bounds stop one request from making thousands of them. The numbers below are the ones this deployment enforces, set by the operator at startup. A request that asks for more than one of them allows gets a 400 that names the bound it crossed. The recent window is not a request parameter at all. It is fixed for every caller.

Deliberately absent

/api/outputs and /api/outputsblocks do not exist here, nor do the /myoutputs, /prove, /rawtx and /checkandpush pages that use them. They need a secret view key or raw transaction hex in a request to a server that could log it.

/api/emission is absent for another reason. It needs a full chain scan or a background scanner, and this explorer keeps no state on disk.
