Paths through the curve tree

To spend an output, its owner proves that it is one of the tree's leaves by climbing from that leaf to the root. The climb needs the output's path: the group of outputs it sits in, and at every layer above, the group holding its ancestor. These are the paths of this transaction's {% if outputs_total == 1 %}output{% else %}outputs{% endif %} as of block {{ as_of }}{% if as_of == tip %}, the tip{% endif %}, each recomputed here from its leaves up.

What a wallet keeps

This is what a wallet needs to spend one of these outputs with FCMP++: the output's path as of the block its spending transaction references. The proof shows that the output is somewhere in the tree without saying where, so spending it gives none of this away. Each block adds outputs at the tree's right edge, which changes the last group of every layer, and with it, sooner or later, the upper groups of every path. So a wallet does not fetch a path once: it keeps its outputs' paths current as it syncs, holding the tree's right edge to do so. It builds them from its own sync, because asking a node for a path tells that node which outputs are yours; monerod's wallet asks only for the outputs of transactions it is told to scan out of order. Looking one up here tells this explorer's operator which outputs you looked at, as any lookup on any explorer does.

Outputs the leaves

Each leaf is an output's one-time key and amount commitment, as they are on the chain. The tree turns them into six numbers: the coordinates of the key, of the point its key image is made from, and of the commitment. For an output from before Carrot it first clears any torsion from the key and commitment, and hashes the key to that point the older way; that is the legacy kind.
