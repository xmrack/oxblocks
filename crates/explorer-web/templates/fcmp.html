An input never points at the output it spends.

Instead of naming its output, each input publishes a disguised copy of it. An output is three points: its key, the point its key image is made from, and its amount commitment. Each gets a fresh random mask, so the copies match no leaf anyone can see, and a fourth point, R, commits to one of those masks for the checks that follow. The masks only come off inside the membership proof, where nobody can watch. The disguised amount doubles as the input's pseudo-output.

A short signature for each input.

Each input carries a small proof that whoever built it knows the secret keys behind the disguised output, and that its key image was made with those same keys. A key image depends only on the output, not on how it was disguised, so spending one output twice shows up as the same key image twice. The proof also signs the transaction, so it cannot be moved onto another one.

RO + e·Õ = sα·G + sy·T

The first shows the prover can open Õ. The second shows L was made with the same x, since sα appears in both. The other two show that P's third value really is the product of the first two, and that its first two are the x in Õ and the ri in R. So z = xri, which is what takes the mask off Ĩ in L.

One proof covers every input.

The largest part. It shows that each disguised output, with its masks taken off, is a leaf of the tree, and climbs from that leaf to the root, without saying which leaf or which branch: every point on the way up is masked inside the proof, so the climb cannot be matched against the tree. The layers alternate between two curves, Selene and Helios, paired so that a point on either can be fed to the other as numbers. So the climb is split between two proofs, one on each curve, each taking every other layer.

Show me the math

The proof is two Generalized Bulletproofs, arithmetic-circuit proofs, one over each curve.{% if let Some(s) = shape %} Here the Selene proof has {{ s.selene_rows }} rows, folded in {{ s.selene_rounds }} rounds, and the Helios proof {{ s.helios_rows }} rows in {{ s.helios_rounds }} rounds.{% endif %} A row is one multiplication. The rows are rounded up to a power of two, and each round halves them and adds two points to the proof.

For each input, the Selene proof first takes the masks off:

O = Õ − ro·T,   I = Ĩ − ri·U,   C = C̃ − rc·G,   R = ri·V + rri·T

with the same ri in I and R. It then checks that the six coordinates of O, I and C are one of the leaves in a list it commits to. That list is committed as a node is, but with a mask:

N′ = Hinit + Σi si·Gi + b·H = N + b·H

So N′ is the leaves' parent N hidden by a fresh mask b on a fixed point H. The Helios proof takes that mask off, N = N′ − b·H, and checks that N's x-coordinate is in the next list, its parent's children, committed the same way. The climb goes on, alternating curves, up to the last list, the root's children, whose N′ is the next step's root′. A short list is padded with zeros, as in the tree.

To show that a value v is in a list s1, …, sk, the circuit shows

(s1 − v)(s2 − v) ··· (sk − v) = 0

which holds only if v is one of them. For the leaves, a random challenge first folds each leaf's six numbers, and the output's, into one. Taking a mask off is an elliptic-curve multiplication, which the circuit checks with a divisor rather than working through it step by step. Ed25519's coordinates are Selene scalars, so the leaves' step is proved on Selene, and from there each proof works on the other curve's points. A verifier sees only the masked N′, never an N, a list, or which member matched. The proof's size follows from the input count and the layer count alone.

Show me the math

An output is three points: its key O = x·G + y·T, its key image generator I = Hp(O), a hash of O onto the curve, and its amount commitment C. A leaf is the x and y coordinates of all three, in Weierstrass form: six numbers, which are exactly Selene scalars. A node commits to its children as

N = Hinit + Σi si·Gi

where Hinit and the Gi are fixed points on the node's curve, with no known relation to each other, so no other list of children gives the same N. At the bottom the si are the leaves' six scalars each, 38 leaves to a Selene node. Above that each si is a child node's x-coordinate: 18 Selene nodes to a Helios node, 38 Helios nodes to a Selene node, and so on up to a single node, the root. A Selene point's coordinates are Helios scalars and a Helios point's are Selene scalars, so each layer feeds the next. Outputs join in order, so only the last node of a layer can have fewer children than the rest, and its missing children count as zero.
